# 漫画でわかる 離婚バイブル ― 制作キット

子どもがいる女性向けの離婚実務書を、**全100ページの漫画**として作り、Kindle（KDP）で
出版するための制作一式。シナリオ・ページプロンプト・表紙指示・KDP登録情報・
ファクトチェック表がそろっている。

---

## 作るとできあがるもの

| ファイル（`out/`） | 中身 | 生成 |
|---|---|---|
| `01_構成案.md` | 章構成・構成バランス・テンプレ配分・全100ページの一覧 | 自動 |
| `02_シナリオ_全100ページ.md` | 全ページ・全コマの場面／セリフ／オノマトペ／コマ位置 | 自動 |
| `03_ページプロンプト集.md` | **1ページ1ブロックの「貼るだけ」プロンプト**＋キャラシート作成＋検品表＋進捗表 | 自動 |
| `04_表紙とキャラシート制作.md` | 表紙イラストのプロンプトと文字入れ指示、キャラシートの合格基準 | 手書き |
| `05_KDP登録シート.md` | タイトル・紹介文・キーワード7枠・カテゴリ・価格・免責ページ・奥付 | 手書き |
| `06_ファクトチェックリスト.md` | 本文の全事実記述と、出版前に確認すべき公式サイト | 手書き |

手書きの3本は `static/` に置いてあり、ビルド時に `out/` へコピーされる。

## 作品仕様（確定・変更禁止）

| 項目 | 値 |
|---|---|
| 総ページ数 | 100ページ |
| 章構成 | 全8章＋巻頭・巻末 |
| コマ数 | 本文4〜5コマ／扉1コマ＋帯 |
| カラー | **モノクロ**（表紙のみフルカラー） |
| 縦横比 | **2:3（1024×1536px）** |
| 製本 | 右綴じ（読み順 右→左） |
| コマ割り | 長編セット T1〜T7 |

**カラーと縦横比は全ページの固定ブロックに焼き込まれている。**
後から変えると100ページ分のプロンプトを作り直すことになるので、変更しない。

## 使い方

### 1. 生成する

```bash
cd manga
python3 validate.py   # ルール違反がないか検査
python3 build.py      # out/ に6ファイルを出力
```

### 2. キャラシートを3枚作る（最初に必ず）

`out/03_ページプロンプト集.md` の「2. STEP 0」にプロンプトが入っている。

- `char_SHINDO.png` … 新藤みやこ（離婚カウンセラー）
- `char_TAKAHASHI.png` … 高橋あかり（主人公）
- `char_RYOSUKE.png` … 高橋涼介（夫）

**3枚がそろうまで本文ページを描き始めない。** 途中で作り直すと、それ以前のページと外見が合わなくなる。

### 3. 本文を1ページずつ描く

守るのは3つだけ。

1. **1ページ = 1新規チャット**（会話履歴に頼らない）
2. **毎回キャラシート画像を添付し直す**（同じファイルを使い回す）
3. **ブロックは丸ごとコピペ。書き換えない**

禁句：「さっきのキャラで」「前のページと同じタッチで」「この画像の顔を直して」
NGのときは修正を頼まず、**新規チャットで引き直す**。

### 4. 10ページごとにグリッドで検品

1枚ずつ見ても差に気づけない。10枚並べて、線の太さ・トーンの濃さ・頭身の揃いを見る。
判定は **50%ルール（ほぼ別人のときだけNG。迷ったらOK）**。

### 5. EPUBにする

描き上がった100枚を1つのフォルダに入れて、`epub_build.py` に渡す。
**右綴じ・固定レイアウトのEPUB**が出てきて、そのままKDPにアップロードできる。

```bash
# まず画像だけ検査する（枚数・サイズ・番号の飛び）
python3 epub_build.py --check ~/pages

# EPUBを作る
python3 epub_build.py ~/pages --cover ~/cover.jpg
# → out/divorce_bible.epub
```

ファイル名は自由でよい。**ファイル名に含まれる数字**でページ順に並べる
（`p001.png` / `1.png` / `ページ01.jpg` など、どれでも可）。

自動で入るもの:

- 右綴じ設定（`page-progression-direction="rtl"`）
- 固定レイアウト（`pre-paginated`）とKindle向けのコミック指定
- 章ごとの目次（`chapters/` のデータから自動生成）
- 免責ページ2枚（本書をお読みになる前に／身の危険を感じている方へ）
- 奥付

書誌情報（著者名・発行者名・発行日）は `epub_build.py` の冒頭を直す。

### 6. 入稿する

`out/05_KDP登録シート.md` の手順どおりに進める。
**`out/06_ファクトチェックリスト.md` を全部確認してから出版ボタンを押すこと。**

## 中身を書き換えるには

シナリオの本体は `chapters/ch00.py` 〜 `ch09.py` にあり、Pythonのデータとして書かれている。
Markdownを直接いじらず、必ずこちらを直して `build.py` を流し直す。

```
manga/
├── spec.py              作品仕様・作画/カラー/漫画ルールの固定ブロック・T1〜T7・背景カタログ
├── characters.py        登場人物（キャラシート3体）とモブの外見文言
├── kit.py               シナリオ記述用のヘルパー（page / pn / say / box など）
├── scenario.py          章ファイルを連結し、章メタを持つ
├── chapters/ch00〜09.py 本文データ（ここを書き換える）
├── static/              手書きドキュメント（04〜06）
├── build.py             out/ を生成
├── epub_build.py        ページ画像 → KDP入稿用の固定レイアウトEPUB
├── validate.py          ルール検査
└── out/                 納品物（生成結果）
```

### `validate.py` が見ているルール

- ページが1〜100の連番になっているか
- コマ数がテンプレ（T1〜T7）と一致しているか／2:3の上限5コマを超えていないか
- 同じテンプレが3ページ以上連続していないか
- **吹き出しの中に句読点（、。）がないか**
- 吹き出し1つ25文字以内・1コマ合計60文字以内か
- **同じコマに吹き出しが2つ以上あるとき、全部に（右）（左）が付いているか**
- 全コマに背景の指定があるか
- 場面に「ト書き」が混入していないか
- 話者がそのページのキャストに入っているか
- モブ記号（`{HINA}` など）が定義されているか
- キャラの髪色・髪型・服色に重複がないか
- 見開きの開始が偶数ページになっているか（右綴じ）

エラーが1件でも出たら、`build.py` を流す前に直す。

## モノクロ運用の注意

本文はモノクロなので、**人物の識別はトーン（明暗）だけが頼り**になる。
`characters.py` では色名ではなくトーンで書いてある。

| キャラ | 髪 | 服 |
|---|---|---|
| 新藤みやこ | ベタ黒 | 濃いトーン |
| 高橋涼介 | 中間トーン | 中間トーン |
| 高橋あかり | 最も淡いトーン | 淡いトーン |

ここが曖昧になると、100ページのどこかで必ず人物が入れ替わる。
キャラシートの段階で、3体を横に並べてトーン差を目視確認すること。
