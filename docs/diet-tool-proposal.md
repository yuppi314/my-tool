# 提案企画書:「1ヶ月-3kgダイエット診断ツール」

作成日: 2026-07-15
作成者: Claude (提案ドラフト)
ステータス: 初期提案(レビュー待ち)

---

## 1. 企画概要

**サービス名(仮)**: 1ヶ月-3kgダイエットナビ

生年月日ではなく「身長・体重・年齢・性別・活動レベル」を入力すると、
科学的根拠(基礎代謝・消費カロリー計算式)に基づいて「1ヶ月で健康的に3kg減量するための
1日の目標摂取カロリー・PFCバランス・行動プラン」を即座に算出する診断ツールです。

既存の `my-tool`(九星気学×マヤ暦診断)と同じ**フリーミアム型マネタイズ構造**
(無料診断でリード獲得 → 有料詳細プランで課金)を踏襲し、実装済みの
Express + SQLite + Stripe 構成をそのまま再利用することで、開発コストを抑えて
短期間でリリースすることを狙います。

## 2. 背景・課題

- 「1ヶ月で3kg痩せたい」という短期目標を持つユーザーは多いが、多くのダイエットアプリは
  長期の体重記録・食事ログが中心で、**今すぐ「何をどれだけ減らせばいいか」が分かるツール**は少ない。
- 3kg/月という目標は、医学的に妥当な範囲(体脂肪1kg≒7,700kcalとして、1ヶ月で
  約23,100kcalの累積カロリー赤字 ≒ 1日あたり約770kcalの調整)であり、
  **数値化して具体的な行動指針を出せる**ことが差別化ポイントになる。
- 無理な急減量(月5kg以上など)を助長しないよう、**安全な範囲に目標を丸める設計**が
  信頼性・コンプライアンス上重要。

## 3. ターゲットユーザー

- 20〜40代で「結婚式・夏・健康診断までにあと3kg落としたい」など明確な短期目標がある層
- ダイエットアプリの継続入力が面倒で、まず「自分の場合はどれくらいのカロリー制限が必要か」を
  知りたいライトユーザー
- SNS(Instagram/X/TikTok)経由の流入を想定(簡易診断→シェアされやすいUI)

## 4. 提供価値・差別化ポイント

| ポイント | 内容 |
|---|---|
| 即時性 | 5項目入力・数秒で「1日の目標カロリー」「減らすべきPFC量」が分かる |
| 科学的根拠 | ミフリン・セントジョール式(BMR)+活動係数(TDEE)+7,700kcal/kg理論を明記し、単なる占いではなく実用ツールとして信頼性を担保 |
| 安全設計 | 目標が急激すぎる場合(例: 体重の5%超/月)は自動で警告・上限緩和を提案し、医療的リスクを回避 |
| パーソナライズ有料プラン | 無料診断は「目標値」まで、有料は「4週間の週別メニュー例・運動プラン・停滞期対策」まで踏み込む |

## 5. 機能一覧

### 5.1 無料機能(リード獲得)

1. **簡易診断フォーム**: 身長・体重・年齢・性別・活動レベル(5段階)・目標体重(または「-3kg」固定選択)を入力
2. **即時結果表示**:
   - 現在のBMR・TDEE(1日の消費カロリー目安)
   - 1ヶ月-3kgに必要な1日の目標摂取カロリー
   - 目標が安全範囲かどうかの判定(安全/やや厳しい/非推奨のいずれか)
   - 簡易PFCバランス(P/F/C グラム数の目安)
3. **メールアドレス登録**でPDF/結果を保存 → `leads` テーブルに保存(既存実装のパターンを流用)
4. **広告枠プレースホルダー**(結果画面に設置、AdSense等を後から差し込み可能)

### 5.2 有料機能(単発課金 or サブスク)

既存実装は「単発課金の詳細レポート」パターンだが、ダイエットは継続性が価値を生みやすいため、
**単発(詳細プランPDF)を先行実装し、将来的にサブスク(進捗トラッキング)へ拡張**する2段階を提案。

1. **4週間ステップ別プラン**(単発 ¥980〜1,480想定):
   - 週ごとの目標カロリー・PFC配分(週1週目は緩やかに、後半で調整するなど停滞期対策込み)
   - 目標に応じた運動プラン例(有酸素/筋トレの目安時間)
   - 挫折しやすいポイントと対策のアドバイス文(既存 `content.js` のようなテンプレ合成方式)
2. **(将来拡張)進捗トラッキング機能**(サブスク想定):
   - 体重を日次記録 → グラフ表示、目標線との乖離をフィードバック
   - LINE/メールでのリマインド通知
3. **簡易管理画面 `/admin.html` 相当**: リード数・診断数・購入数・売上・コンバージョン率(既存実装を流用)

## 6. 計算ロジック(核心部分)

既存プロジェクトの「九星気学」「マヤ暦」ロジックに相当する、本ツールの中核ロジック。

1. **BMR(基礎代謝)**: ミフリン・セントジョール式
   - 男性: `10×体重kg + 6.25×身長cm − 5×年齢 + 5`
   - 女性: `10×体重kg + 6.25×身長cm − 5×年齢 − 161`
2. **TDEE(総消費カロリー)**: `BMR × 活動係数`(1.2〜1.9の5段階)
3. **必要カロリー赤字**: `3kg × 7,700kcal ÷ 30日 ≒ 770kcal/日`
4. **目標摂取カロリー**: `TDEE − 770kcal`(下限は性別ごとの最低推奨カロリー、例: 女性1,200kcal/男性1,500kcalを下回らないようガード)
5. **安全判定**: 目標体重減少が「現体重の5%/月」を超える場合は警告表示し、
   「3kgではなくX kg/月」の現実的な代替提案を返す
6. **PFCバランス**: 目標カロリーに対し P=体重×1.6g、F=総カロリーの20〜25%、残りをCで按分

## 7. 画面構成(ワイヤーフレーム概要)

```
public/
  index.html    診断フォーム(身長・体重・年齢・性別・活動レベル入力)
  result.html   無料結果(BMR/TDEE/目標カロリー/安全判定) + 有料プランへの導線
  plan.html     購入後の4週間詳細プラン表示
  admin.html    管理ダッシュボード(既存を流用)
```

## 8. 技術スタック・ディレクトリ構成案

既存リポジトリの技術スタックをそのまま再利用(Node.js未経験でも運用しやすい既存パターンを維持)。

```
src/
  server.js
  db.js                  leads / diagnoses / orders (既存スキーマをほぼ流用可)
  lib/
    calorie.js           BMR/TDEE/目標カロリー計算(新規, kyusei.js相当)
    macro.js             PFCバランス計算(新規, mayan.js相当)
    plan.js              4週間プラン文言の合成(新規, content.js相当)
  routes/
    diagnosis.js          無料診断・詳細プランAPI(既存流用・改修)
    payment.js             Stripe Checkout・Webhook(既存をほぼそのまま流用)
    admin.js                管理統計API(既存流用)
```

- **サーバー**: Express + SQLite(better-sqlite3)
- **決済**: Stripe Checkout(単発課金、モックモード対応で無料デプロイも可能)
- **デプロイ**: Render.com(既存 `render.yaml` の構成を流用、無料プランでまず公開可)

## 10. 法的・倫理面の注意事項

- 医療行為・医師の診断ではないことを明記(既存プロジェクトの免責パターンを踏襲)
- 過度な急減量を助長しないよう、安全範囲を超える入力には必ず警告文を表示
- 特定商取引法に基づく表記・利用規約・プライバシーポリシーは既存テンプレート(`tokushoho.html`等)を流用し、
  事業者情報を確定後に差し替え
