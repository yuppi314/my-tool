# 要件定義書

## 1. 概要

| 項目 | 内容 |
|---|---|
| プロダクト名 | 九星気学 × マヤ暦 診断ツール |
| 目的 | 生年月日から「九星気学の本命星」と「マヤ暦(ドリームスペル方式)のKIN・太陽の紋章・銀河の音」を算出し、無料の簡易診断からリードを獲得したうえで、有料の詳細鑑定レポート・相性診断へアップセルするフリーミアム型のマネタイズWebサービス |
| 想定利用者 | 占い・スピリチュアル系コンテンツに関心のある一般ユーザー(BtoC) |
| 収益モデル | 単発課金(詳細レポート ¥980/回、`REPORT_PRICE_JPY`で変更可)、広告枠、メールリードの再利用 |

## 2. 用語

- **本命星**: 九星気学における生まれ年から算出される9種類の星(一白水星〜九紫火星)。
- **KIN**: マヤ暦(13の月の暦/ドリームスペル方式)における1〜260の通し番号。
- **太陽の紋章**: KINから導出される20種類のシンボル。
- **銀河の音**: KINから導出される13種類の音(バイブレーション)。
- **診断(diagnosis)**: 1回の生年月日入力によって生成される診断結果1件を指すレコード。
- **リード(lead)**: 無料診断時に入力されたメールアドレス等、マーケティング目的で保存される見込み客情報。

## 3. 全体フロー(マネタイズ導線)

1. トップページ(`/`, `public/index.html`)で生年月日(必須)・氏名(任意)・メールアドレス(任意)を入力し、無料診断を実行する。
2. サーバーは本命星・KINを算出し、`diagnoses` テーブルに保存。メールアドレス入力があれば `leads` テーブルにも保存する。
3. 無料結果画面(`public/result.html`)に本命星・KIN・太陽の紋章・銀河の音の概要を表示し、広告枠を1箇所表示する。
4. 「詳細レポートを見る」導線からStripe Checkoutへ遷移し、決済完了で `diagnoses.paid` が `1` になる。
5. 詳細レポート(性格詳細・今年の運気サイクル・今月の運勢・アドバイス)を購入者に表示する。
6. 詳細レポート購入者限定で、パートナーの生年月日を入力する相性診断(五行相性スコア)を利用できる。
7. 運営者は `/admin.html` からトークン認証付きでリード数・診断数・購入数・売上・コンバージョン率を確認する。

## 4. 機能要件

### 4.1 無料診断機能

- 入力: 生年月日(必須、`YYYY-MM-DD`)、氏名(任意)、メールアドレス(任意)。
- バリデーション: 生年月日が `YYYY-MM-DD` 形式かつ有効な日付であること。不正な場合は400エラーを返す。
- 処理: 生年月日から本命星ID・KINを算出し、診断結果を新規IDで永続化する。
- 出力: 本命星名、KIN、太陽の紋章、銀河の音を含む簡易結果。
- 再取得: 発行済みの診断IDを指定して、同じ簡易結果と購入済みフラグ(`paid`)を再取得できる。

### 4.2 詳細レポート機能(有料)

- 未購入の診断IDに対して詳細レポートを要求した場合、402エラー(決済誘導)を返す。
- 購入済みの診断IDに対しては、性格詳細・今年の運気サイクル・今月の運勢・アドバイスを含む詳細結果を返す。

### 4.3 決済機能

- 診断IDを指定して決済セッションを作成する。
- `STRIPE_SECRET_KEY` 未設定時は開発用モックモードとして動作し、即座に購入済み扱いにする。
- `STRIPE_SECRET_KEY` 設定時はStripe Checkoutセッションを作成し、成功/キャンセルURLへリダイレクトする。
- Stripe Webhook(`POST /webhook/stripe`)で `checkout.session.completed` イベントを受信し、署名検証のうえ該当診断を購入済みに更新し、注文ステータスを `paid` にする。
- 注文情報(`orders`)には診断ID・Stripeセッション ID・金額・ステータスを記録する。

### 4.4 相性診断機能(購入者限定)

- 詳細レポート未購入の診断IDでは402エラーを返す。
- 購入済みの診断ID・パートナーの生年月日(必須、バリデーションあり)を受け取り、五行相性理論に基づく相性スコアを算出して返す。
- 自分とパートナー双方の簡易結果、および相性診断結果を返す。

### 4.5 管理画面機能

- `/admin.html` から統計情報を閲覧できる。
- アクセスにはクエリパラメータまたはヘッダーで `ADMIN_TOKEN` と一致するトークンを要求し、不一致の場合401エラーを返す。
- 表示項目: リード数、診断数、購入数、売上(円)、コンバージョン率(%)。

### 4.6 広告枠

- 無料結果画面・詳細レポート画面に広告枠プレースホルダーを設置する。
- 実運用時はGoogle AdSense等のタグを差し込むことで収益化できる構造とする。

### 4.7 法的ページ

- 特定商取引法に基づく表記(`tokushoho.html`)、利用規約(`terms.html`)、プライバシーポリシー(`privacy.html`)のテンプレートを提供する。
- 娯楽目的である旨の免責表記をトップページに含める。
- 公開前に事業者情報のプレースホルダーを実データに置き換える運用ルールとする。

## 5. 非機能要件

- **データ永続化**: 開発・小規模運用はSQLite(`better-sqlite3`)を使用。無料プラン(永続ディスクなし)ではデータが再起動時にリセットされる制約を許容する。本格運用時はDocker + 永続ディスク構成に切り替える。
- **決済セキュリティ**: Stripe Webhookは署名検証(`STRIPE_WEBHOOK_SECRET`)を必須とし、raw bodyで検証を行う。
- **CORS**: APIは `cors` ミドルウェアにより許可する。
- **環境変数**: `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` / `BASE_URL` / `REPORT_PRICE_JPY` / `ADMIN_TOKEN` / `PORT` により挙動を制御する。
- **計算ロジックの出自**: 九星気学・マヤ暦の算出ロジックは特定流派の非公開ロジックではなく、公開されている一般的な計算方式を採用する。

## 6. データモデル(現状のスキーマ)

### leads
| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | 自動採番 |
| email | TEXT NOT NULL | リードのメールアドレス |
| name | TEXT | 氏名(任意) |
| birthdate | TEXT | 生年月日 |
| created_at | TEXT | 作成日時 |

### diagnoses
| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT PK | 診断ID(UUID) |
| birthdate | TEXT NOT NULL | 生年月日 |
| name | TEXT | 氏名(任意) |
| email | TEXT | メールアドレス(任意) |
| honmei_star | INTEGER NOT NULL | 本命星ID |
| kin | INTEGER NOT NULL | マヤ暦KIN |
| paid | INTEGER NOT NULL DEFAULT 0 | 購入済みフラグ |
| created_at | TEXT | 作成日時 |

### orders
| カラム | 型 | 説明 |
|---|---|---|
| id | INTEGER PK | 自動採番 |
| diagnosis_id | TEXT NOT NULL | 対象診断ID(FK） |
| stripe_session_id | TEXT | Stripe Checkoutセッション ID |
| amount | INTEGER | 金額(円) |
| status | TEXT NOT NULL DEFAULT 'pending' | `pending` / `paid` / `paid_mock` |
| created_at | TEXT | 作成日時 |

## 7. API一覧

| メソッド | パス | 概要 | 認証/制限 |
|---|---|---|---|
| POST | `/api/diagnosis` | 無料診断を作成しリードを保存 | なし |
| GET | `/api/diagnosis/:id` | 簡易結果の再取得 | なし |
| GET | `/api/diagnosis/:id/full` | 詳細レポート取得 | 購入済みのみ(402で誘導) |
| POST | `/api/checkout` | 決済セッション作成 | なし(Stripe未設定時はモック決済) |
| POST | `/webhook/stripe` | Stripe Webhook受信 | 署名検証必須 |
| POST | `/api/compatibility` | 相性診断 | 購入済みのみ(402で誘導) |
| GET | `/api/admin/stats` | 管理統計取得 | `ADMIN_TOKEN`必須 |
| GET | `/health` | ヘルスチェック | なし |

## 9. デプロイ要件

- 無料公開: Render.comの無料プラン(`render.yaml`のBlueprint)でカード登録不要にてデプロイ可能。ただし永続ディスクなしのためデータは再起動時にリセットされる。
- 本格運用: `Dockerfile`を用いてDocker対応ホスティングにデプロイし、`/app/data`に永続ディスクをマウントすることでSQLiteデータを永続化する。

## 10. 現状のスコープ外(今後の検討事項)

- 会員登録・ログイン機能(現状は診断IDベースの匿名利用)。
- 詳細レポートの多言語対応。
- 決済手段のStripe以外への対応。
- 本命星・マヤ暦以外の占術(例: 星座、タロット等)の追加。
