## 0. プロジェクトコードネーム(仮称)

**コードネーム: 「MITSU(ミツ)」**(「見積もり」から命名。将来の変更可)

---

## 1. プロジェクト概要

「見積書を作るソフト」ではなく、「見積書づくりを入り口にした、フリーランス・個人事業主のためのAI業務アシスタント」。

### コアUXフロー(最重要方針)
```
① ユーザーが自然な言葉で話しかける
② AIが対話しながら情報を補う
③ AIが見積書のたたき台を提示、ユーザーが金額・文言を確認
④ 見積書PDFが完成
```

### 重要な設計原則
**AIが使えない状況でも、すべての基本機能は手入力で完結できること。** AIはあくまで補助であり必須ではない。

---

## 2. MVP(Version 0.1)

### 含める機能(6つ)
1. 会社情報(ロゴ・住所・振込先などの登録)
2. 顧客管理(登録・編集・検索)
3. 見積書作成(品目・数量・単価・税額・合計。手入力でも完結可能)
4. PDF出力
5. AI入力補助(自然文→AI対話→見積項目の自動組み立て。任意機能)
6. データのエクスポート/インポート(バックアップ・復元)

### 含めないもの
- 見積書→請求書変換 / 履歴検索の高度化 / AIメール作成・AI価格チェック(→Version 0.2候補) / クラウド同期・会計連携等(→将来機能)

## 5. 解決する課題
1. 見積書作成という「入力作業」を対話でゼロに近づける
2. 消費税・合計金額の計算ミス防止
3. 「何をどう書けばいいか」の心理的ハードル解消
4. (将来)メール文面・価格設定の業務判断もAIが支援

## 6. 競合分析

| サービス | 形態 | 強み | 弱み |
|---|---|---|---|
| Misoca(弥生) | クラウド | 会計ソフト連携 | 月額必須、AI対話なし |
| freee請求書 | クラウド | freeeエコシステム | 囲い込み、月額費用 |
| MakeLeaps | クラウド | 郵送代行 | 個人には過剰 |
| board | クラウド | 案件管理統合 | 学習コスト高 |
| Excel/Word | 手動 | 無料 | 手作業・ミス多発、AI要素なし |

## 7. 競合が簡単に真似できない機能
1. 対話型見積フロー自体(UIの土台から作り直しが必要)
2. 業務文脈の理解(使われるほど資産が溜まる)
3. AIプロバイダー非依存のアーキテクチャ(8番)
4. オフライン完結型のデスクトップアプリという立ち位置

## 8. AIアーキテクチャ方針

- **Version 0.1**: ユーザー自身のAPIキー設定方式(BYOK)を基本とする
- **将来方針**: 運営提供APIにも対応できるよう、「AIプロバイダー(Claude/OpenAI/Gemini)」×「APIキー提供元(ユーザー/運営)」の2軸を最初から分離した設計とする

## 9. 必須機能(Version 0.1 詳細)

| # | 機能 | 説明 |
|---|---|---|
| 1 | 会社情報登録 | ロゴ・住所・振込先・電話番号等 |
| 2 | 顧客管理 | 登録・編集・削除・検索 |
| 3 | 見積書作成 | 自動計算。AIなしで全項目手入力完結可能 |
| 4 | AI入力補助 | 自然文→対話→自動組み立て。ユーザー自身のAPIキーが必要。未設定時は本機能のみ無効化、他機能に影響なし |
| 5 | PDF出力 | 印刷可能レイアウトでPDF保存 |
| 6 | データのエクスポート/インポート | 全データのバックアップ・復元 |

## 12. 非機能要件

| 項目 | 要件 |
|---|---|
| 性能 | 主要操作(入力→PDF生成)は3秒以内 |
| 対応OS | Windows 10/11、macOS(最新2バージョン程度) |
| オフライン動作 | AI入力補助以外の全機能はオフラインで完結 |
| AI非依存性 | AI機能が利用不可でも他の全基本機能に影響しない |
| データ保存 | ローカルDB、再起動後もデータ維持 |
| バックアップ | データエクスポート/インポート機能(MVP必須) |
| 拡張性 | AIプロバイダー・キー提供元切り替え、将来のクラウド同期に対応できる構造 |
| 保守性 | 機能追加時に既存機能を壊さない設計・テスト体制 |

## 13. セキュリティ要件

| 項目 | 要件 |
|---|---|
| データ保護 | 顧客情報のローカル暗号化保存 |
| APIキーの保護 | 平文保存せず、OS標準の資格情報ストア等で安全に保管 |
| アプリロック | 起動時のパスコード/パスワードロック |
| 通信の暗号化 | AI通信はHTTPS必須 |
| 個人情報保護 | 個人情報保護法に準拠、不要な外部送信をしない |
| アップデートの安全性 | 署名済みインストーラでの配布 |
| バックアップファイルの保護 | パスワード保護 or 暗号化を検討 |

## 14. 保守方針
- AIプロバイダー抽象化を最優先の設計原則とする
- データ形式のバージョニングとマイグレーション設計(後方互換性)
- テストを書きながらの開発、機能追加時の既存機能への影響確認

## 15. 販売戦略

| モデル | 内容 | メリット | デメリット |
|---|---|---|---|
| Free版 | 基本機能無料、AI機能は制限(要ユーザー自身のAPIキー) | 獲得ハードルが低い | 収益化導線が別途必要 |
| 買い切りPro版 | 一括購入でAI機能含め無制限利用 | サブスク疲れ層に刺さる | Version0.1はBYOKのためAIコストは運営負担なし。収益は買い切りのみで継続性に課題 |
| AIサブスク版(将来) | 運営提供APIによる月額課金 | 継続収益、AIコストと収益が連動 | Version0.1では未対応 |

Version 0.1時点の方向性: **Free版+買い切りPro版**の2本立てで販売開始し、Version 0.2以降で「AIサブスク版」を追加。

## 16. Version 0.1 成功条件

**初めて使うユーザーが、5分以内に見積書を1件作成し、PDF保存まで完了できること。**

| 項目 | 基準 |
|---|---|
| 完了時間 | 会社情報・顧客登録が済んだ状態から見積書作成〜PDF保存まで5分以内 |
| 迷わず完了できるか | 操作説明なしで、ペルソナB(ITリテラシー低め)でも完了できること |
| AI補助ありの場合 | 手入力より明確に速いと感じられること |
| エラー率 | 初回利用時に致命的な操作エラー(データ消失・クラッシュ)が発生しないこと |
