## デザイン原則

1. **迷わない導線を最優先する**: ペルソナB(ITリテラシー低め)が操作説明なしで完了できることを基準にする(要件定義16番の成功条件と直結)
2. **AIは主役だが強制しない**: AI対話パネルは常に見積書エディタの「任意の右サイドパネル」として配置し、フォーム入力によるメインフローを隠したり塞いだりしない
3. **金額のミスは致命的**: 自動計算結果(小計・税額・合計)は画面上で最も目立つ位置・サイズで表示する
4. **5分で完了できる導線**: 新規見積書作成〜PDF保存までのクリック数・入力ステップを最小限にする。不要な確認ダイアログを挟まない
5. **AI機能が使えない状態を「壊れた状態」に見せない**: APIキー未設定時もエラー然とした表示にせず、「使うと便利な追加機能」として穏やかに案内する([06のワイヤーフレーム参照](./06-wireframes.md))

## トーン&マナー

- 帳票を扱うアプリのため、派手な色や過度なアニメーションは避け、信頼感のある落ち着いたトーンにする
- AI対話パネルは他の画面要素と視覚的に区別できるよう、アクセントカラー・アイコン(🤖等)を用いる
- 金額表示は等幅フォントを使用し、桁のずれによる誤読を防ぐ

## アクセシビリティ

- 文字サイズを設定画面から調整できるようにする(将来検討、Version 0.1では標準サイズのみでもよい)
- テキストと背景のコントラスト比はWCAG AA目安を満たす
- キーボード操作(Tab移動、Enterで送信)に対応する

## エラー表示の考え方([14. エラーハンドリング設計](./14-error-handling.md)と連携)

- 入力バリデーションエラーは該当フィールドの直下にインライン表示し、モーダルで画面全体を遮らない
- AI関連のエラーはAIパネル内に留め、他の操作(手入力)をブロックしない

## レイアウト方針

- デスクトップ専用アプリのため、主要解像度(1366×768以上)を基準にレイアウトを組む
- ウィンドウリサイズへの追従は最低限(極端な縮小時の崩れ防止)に留め、モバイル対応のような複雑なレスポンシブ設計はMVPでは行わない
