## ライブラリ

`electron-log` を採用(自前実装を避け、ローテーション・レベル管理を標準機能に任せる。[02. 技術スタック選定](./02-tech-stack.md)参照)。

## 出力先

`app.getPath('userData')/logs/app.log`

| OS | 実際のパス例 |
|---|---|
| Windows | `%APPDATA%/MITSU/logs/app.log` |
| macOS | `~/Library/Application Support/MITSU/logs/app.log` |

## レベル

`DEBUG < INFO < WARN < ERROR`。本番ビルドはINFO以上を出力、開発ビルドはDEBUGまで出力する。

## フォーマット

```
[YYYY-MM-DD HH:mm:ss] [LEVEL] [module] message
```

## ローテーション

1ファイル最大5MB、直近3世代を保持(`app.log`, `app.log.1`, `app.log.2`)。

## 記録する内容

- アプリの起動/終了
- DB操作の成否(件数レベル。中身の詳細は記録しない)
- AI呼び出しの成否(成功/失敗種別のみ。リクエスト本文・レスポンス本文は記録しない)
- PDF生成/保存結果
- バックアップのエクスポート/インポート結果
- エラー全般(分類・発生箇所)

## 記録しないもの(マスキング必須)

- **APIキー**(いかなる形式でも)
- 顧客の詳細な個人情報(住所・金額等)。顧客名程度の識別情報は許容するが、本文全体は記録しない

## フィードバックとの連携

[16. フィードバック送信設計](./16-feedback.md)では、ログの自動添付は行わず、ログファイルの保存場所をユーザーに案内するに留めます(実装のシンプルさ優先)。
