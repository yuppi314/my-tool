## 方針

MVP必須機能(要件定義2番・9番)として、ユーザーが自分のPCが壊れたり買い替えたりしても、1つのファイルでデータを復元できるようにします。

## エクスポート形式

拡張子 `.mitsubackup`(実体はZIP)。

```
backup_20260717.mitsubackup (zip)
├── manifest.json     # schema_version, app_version, exported_at
├── data.json         # company_info / customers / quotes / quote_items の全データ
└── assets/
    └── logo.png      # 会社ロゴ等のアセット
```

**APIキーはバックアップに含めません**(要件定義13番: バックアップファイルの保護、セキュリティ方針)。復元後はAI設定タブでの再入力が必要になる旨を、インポート完了時に案内します。

## フロー

```mermaid
flowchart TD
    subgraph Export[エクスポート]
        E1[エクスポート実行] --> E2[DB全テーブル読み出し]
        E2 --> E3[data.json生成]
        E3 --> E4[ロゴ等アセット収集]
        E4 --> E5[ZIP圧縮]
        E5 --> E6[保存先を選択して書き出し]
    end
    subgraph Import[インポート]
        I1[インポート実行] --> I2[ZIP展開]
        I2 --> I3{schema_version確認}
        I3 -->|対応可能| I4[上書き確認ダイアログ]
        I4 --> I5[マイグレーション適用]
        I5 --> I6[DBへ反映]
        I3 -->|非対応(新しすぎる)| I7[エラー表示]
    end
```

## 詳細ルール

- **上書き確認**: インポートは既存データを置き換えるため、実行前に必ず確認ダイアログを表示する(誤操作防止)
- **バージョン互換性**: `manifest.json`の`schema_version`が現在のアプリより古い場合は、[08. データベース設計](./08-database.md)のマイグレーション処理を適用してから取り込む。逆に新しすぎる場合(古いアプリバージョンに新しいバックアップを読み込もうとした場合)は「対応していないバージョンです。アプリを最新版に更新してください」と案内する
- **完了後**: ダッシュボードに遷移し、データが反映されたことを一覧で確認できるようにする
