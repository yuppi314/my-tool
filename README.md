# 今月の吉方位 × マイル旅 診断ツール

生年月日とお住まいの地域から、九星気学で「今月の最大吉方(年盤・月盤の両方で吉となる方位)」を算出し、
自宅から100km以上離れた、マイルで行ける旅先を提案するフリーミアム型のマネタイズツールです。
診断・決済・コンテンツの提供・週次レポートまで自動で動くので、寝ている間も集客と販売が回る構成になっています。

## マネタイズの仕組み

1. **無料診断でリード獲得**: 生年月日・お住まい(住所・現在地・近くの都市のいずれか)・メールアドレスを入力すると、今月の吉方位盤とおすすめ旅先(方位ごとに3件)を表示します。メールは `leads` テーブルとGoogleスプレッドシートに保存され、節入りのたびに「今月の吉方位メール」が自動で届きます(下記「メールリストの保管と毎月の吉方位メール」)。
2. **アフィリエイト(紹介料)**: 結果ページに「旅の準備」枠(PR表記付き)を用意しています。`src/data/affiliates.js` の `url` に、ASPで提携したマイル系クレジットカード・ホテル予約・航空券などの広告URLを入れると表示されます。
3. **月額会員(月¥480、`SUBSCRIPTION_PRICE_JPY`で変更可)**: 12ヶ月の吉方位カレンダー(月ごとの最大吉方と、その方位の全旅先)を閲覧できます。吉方位は毎月変わるため、継続する理由が自然にあります。解約は結果ページのボタンからいつでも可能です(Stripeでは請求期間の終了時に解約)。
4. **買い切り(¥980、`REPORT_PRICE_JPY`で変更可)**: 月額が苦手な人向けに、同じカレンダーを1回の支払いで閲覧できます。
5. **簡易管理画面 `/admin.html`**: リード数・診断数・購入数・売上・コンバージョン率・月額会員数・MRRをトークン認証付きで確認できます(`ADMIN_TOKEN`で保護)。
6. **週次KPIレポート `GET /api/admin/weekly-report`**: 直近7日と前の7日を比較し、無料診断数・メール登録率・販売・新規会員・解約・有料転換率・MRRと、目標(メール登録率30%・有料転換率3%・解約率10%)を下回った項目の改善アラートを返します。`summary` はそのままSlack/LINEに貼れる文面です。管理画面にも表示され、ワンクリックでコピーできます。

7. **SNS投稿のネタ元 `npm run sns:facts`**: 今月・来月の最大吉方を9つの本命星ぶん、東京・大阪・福岡発の旅先例つきで出力します。毎週日曜の投稿文づくりは、この計算結果だけを根拠に行います(吉方位を推測で書かないため)。
8. **方位マップ画像 `scripts/sns-map.js`**: 出発地から見た今月の最大吉方を日本地図上に塗り、方位にある旅先を番号で示す Instagram 用画像(1080x1350)を、本命星ごとに自動生成します(表紙・お休みの星のまとめ付き)。例: `NODE_PATH=$(npm root -g) node scripts/sns-map.js 2026-10-15 tokyo out/`
9. **文字スライド画像 `scripts/sns-images.js`**: マイル術などの文字中心の投稿用に、スライド定義(JSON)から同じデザインの 1080x1350 の JPEG を生成します。Playwright は依存に含めていないため、インストール済みの環境で `NODE_PATH=$(npm root -g) node scripts/sns-images.js slides.json out/` のように実行します。

## セットアップ

```bash
npm install
cp .env.example .env
npm start
```

`http://localhost:3000` にアクセスすると診断フォームが表示されます。

### Stripe決済について

`STRIPE_SECRET_KEY` を設定しない場合、有料コンテンツの販売は**停止**し、結果ページには「近日スタート予定」と表示されます(公開サイトで誰でも無料で有料機能を開けてしまわないため)。
開発時は `.env` で `MOCK_PAYMENTS=true` にすると、「月額会員になる」「買い切りで見る」ボタンで即座に購入済み扱いになります(`.env.example` は true になっています)。

本番で実際に課金する場合は以下を設定してください。

```
STRIPE_SECRET_KEY=sk_live_xxx (またはテスト用 sk_test_xxx)
STRIPE_WEBHOOK_SECRET=whsec_xxx
BASE_URL=https://your-domain.example.com
```

Stripeダッシュボードで Webhook エンドポイント `POST /webhook/stripe` を登録し、
`checkout.session.completed`・`customer.subscription.updated`・`customer.subscription.deleted` イベントを購読してください
(後ろ2つは月額会員の更新・解約の反映に使います)。

## 計算ロジックについて

- **本命星**: 立春(2/4)を年の区切りとし、生まれ年の西暦を1桁になるまで足した値から `11 - n` で算出する一般的な方法です。
- **年盤・月盤**: 年盤の中宮星は本命星と同じ計算で求めます。月盤は、寅月(2月)の中宮星を年の十二支で決め(子卯午酉年→八白、丑辰未戌年→五黄、寅巳申亥年→二黒)、そこから1ヶ月ごとに1つずつ戻します。月の区切りは節入り日(概算の固定日)です。
- **最大吉方**: 年盤・月盤の両方で、五黄殺・暗剣殺・本命殺・本命的殺・歳破(年盤)/月破(月盤)にあたらず、本命星と相生・比和の星が回座している方位です。本命星が中宮に入る盤は「八方塞がり」として吉方位なしとします。月命星による月命殺・月命的殺は考慮していません。
- **方位の基準地点**: 住所は国土地理院の住所検索API(`/api/geocode` がサーバー側で中継)で座標に変換します。番地・丁目は落とした地名と、小数第2位(約1km)に丸めた座標だけを保存します。ブラウザの現在地、または21都市からの選択にも対応しています。
- **方位の区分**: 東西南北を各30度、四隅を各60度とし、真北基準・大圏コースの出発方位(正距方位図法)で判定します。

2026年9月〜11月の年盤・月盤と、本命星ごとの最大吉方は、九星気学の実務者が目視で確認済みです(2026-09-25)。
吉方位の取り方は流派によって異なります。独自のやり方に合わせたい場合は `src/lib/houi.js` の判定条件を変更してください。
旅先の追加・紹介文の変更・必要マイル目安の更新は `src/data/places.js` を編集してください。

## 法的な注意事項

`public/index.html` 等に「娯楽目的である」旨の免責表記を入れています。
`public/tokushoho.html`(特定商取引法に基づく表記)・`public/terms.html`(利用規約)・`public/privacy.html`(プライバシーポリシー)の
事業者名・住所などは、HTMLを編集せず**環境変数で設定**します(`src/lib/operator.js` が `{{OPERATOR_NAME}}` などに差し込みます)。

| 環境変数 | 内容 |
|---|---|
| `OPERATOR_NAME` | 事業者名(屋号) |
| `OPERATOR_REPRESENTATIVE` | 運営統括責任者(氏名) |
| `OPERATOR_ADDRESS` | 所在地 |
| `OPERATOR_PHONE` | 電話番号 |
| `OPERATOR_EMAIL` | 問い合わせ用メールアドレス |
| `LEGAL_ENACTED_DATE` | 規約・ポリシーの制定日(例: 2026年11月1日) |
| `OPERATOR_COURT` | 管轄裁判所(任意。空なら「当方の所在地を管轄する地方裁判所」) |

未設定の項目はページ上に赤字の「[未設定: …]」で表示され、**1つでも空だとStripeを設定していても有料の新規申し込みは停止**します
(空欄のまま販売すると特定商取引法違反になるため)。
個人事業主で自宅の住所・電話番号を公開したくない場合は、`OPERATOR_ADDRESS` / `OPERATOR_PHONE` に
「請求があった場合には遅滞なく開示いたします」と入れる方法があります(請求があれば実際に開示が必要です)。バーチャルオフィスの住所を使う方法もあります。

メールアドレス欄の下には、毎月の吉方位メールの配信に同意する旨と、配信停止できる旨を表示しています(特定電子メール法のオプトイン)。

## メールリストの保管と毎月の吉方位メール

`LEADS_WEBHOOK_URL` を設定すると、メール登録をGoogleスプレッドシートにも保存します(`src/lib/leadSync.js`)。
無料プランでサーバーのデータが消えても、メールリストは残ります。
スプレッドシート側の Google Apps Script(`scripts/google-apps-script/Code.gs`)が、節入りのたびに登録者へ
今月の最大吉方とおすすめ旅先をGmailで自動送信し、配信停止リンクも付けます。設定手順は `scripts/google-apps-script/README.md` を参照してください。

## デプロイ

### 無料で最短公開する(カード登録不要・初めての方向け)

決済(Stripe)の設定をしなくても、無料診断部分は今すぐ公開できます。以下の手順で進めてください。

1. [Render.com](https://render.com) にアクセスし、GitHubアカウントで無料サインアップ(クレジットカード登録は不要です)。
2. ダッシュボードで「New +」→「Blueprint」を選び、`yuppi314/my-tool` リポジトリを選択します。
3. リポジトリ内の `render.yaml` を自動で読み込み、無料プランのWeb Serviceが作成されます。
4. `BASE_URL` の入力を求められたら、Renderが発行するURL(例: `https://kippou-mile-travel.onrender.com`)を入力します(一度作成してURLが確定してから設定し直しても構いません)。
5. `ADMIN_TOKEN` は好きな文字列(他人に推測されにくいもの)を入力してください。
6. 数分待つとURLが発行され、誰でもアクセスして無料診断が使えるようになります。

> 注意: 無料プランは永続ディスクが使えないため、Renderが再起動(15分アクセスがないと休止→次のアクセスで再起動)するとリード・診断データはリセットされます。
> 診断結果のURLには本命星と丸めた地点が含まれるため、データが消えても無料の結果ページは表示し続けられます。
> 「ユーザーが増えてきたので有料プランにしたい」というタイミングで、`runtime: docker` + 永続ディスク構成に切り替えてください(下記「本格運用する場合」参照)。

決済(カレンダーの買い切り・月額会員)は `STRIPE_SECRET_KEY` を設定するまで販売停止(近日公開表示)なので、
このステップでは何も設定しなくて大丈夫です。準備ができたら教えてください、Stripe連携を一緒に進めます。

### 本格運用する場合(Docker + 永続ディスク)

ユーザー数が増え、リードや購入データを失いたくない段階になったら、Docker + 永続ディスクの構成に切り替えます。

`Dockerfile` を用意しているため、Docker対応のホスティング(Render / Railway / Fly.io など)にそのままデプロイできます。
SQLiteでデータを永続化するため、コンテナの `/app/data` に永続ディスク(ボリューム)をマウントしてください。

Renderの場合は `render.yaml` の `runtime` を `docker` に、`plan` を `starter` 以上に変更し、
`disk` セクション(`mountPath: /app/data`)を追加してください。`STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` も
このタイミングで環境変数に設定します。

手動でDockerを動かす場合:

```bash
docker build -t kippou-mile-travel .
docker run -p 3000:3000 -v $(pwd)/data:/app/data --env-file .env kippou-mile-travel
```
