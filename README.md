# 今月の吉方位 × マイル旅 診断ツール

生年月日とお住まいの地域から、九星気学で「今月の最大吉方(年盤・月盤の両方で吉となる方位)」を算出し、
自宅から100km以上離れた、マイルで行ける旅先を提案するフリーミアム型のマネタイズツールです。
診断・決済・コンテンツの提供・週次レポートまで自動で動くので、寝ている間も集客と販売が回る構成になっています。

## マネタイズの仕組み

1. **無料診断でリード獲得**: 生年月日・お住まい(住所・現在地・近くの都市のいずれか)・メールアドレスを入力すると、今月の吉方位盤とおすすめ旅先(方位ごとに3件)を表示します。メールは `leads` テーブルに保存され、毎月の吉方位のお届けなどに使えます。
2. **アフィリエイト(紹介料)**: 結果ページに「旅の準備」枠(PR表記付き)を用意しています。`src/data/affiliates.js` の `url` に、ASPで提携したマイル系クレジットカード・ホテル予約・航空券などの広告URLを入れると表示されます。
3. **月額会員(月¥480、`SUBSCRIPTION_PRICE_JPY`で変更可)**: 12ヶ月の吉方位カレンダー(月ごとの最大吉方と、その方位の全旅先)を閲覧できます。吉方位は毎月変わるため、継続する理由が自然にあります。解約は結果ページのボタンからいつでも可能です(Stripeでは請求期間の終了時に解約)。
4. **買い切り(¥980、`REPORT_PRICE_JPY`で変更可)**: 月額が苦手な人向けに、同じカレンダーを1回の支払いで閲覧できます。
5. **簡易管理画面 `/admin.html`**: リード数・診断数・購入数・売上・コンバージョン率・月額会員数・MRRをトークン認証付きで確認できます(`ADMIN_TOKEN`で保護)。
6. **週次KPIレポート `GET /api/admin/weekly-report`**: 直近7日と前の7日を比較し、無料診断数・メール登録率・販売・新規会員・解約・有料転換率・MRRと、目標(メール登録率30%・有料転換率3%・解約率10%)を下回った項目の改善アラートを返します。`summary` はそのままSlack/LINEに貼れる文面です。管理画面にも表示され、ワンクリックでコピーできます。

7. **SNS投稿のネタ元 `npm run sns:facts`**: 今月・来月の最大吉方を9つの本命星ぶん、東京・大阪・福岡発の旅先例つきで出力します。毎週日曜の投稿文づくりは、この計算結果だけを根拠に行います(吉方位を推測で書かないため)。
8. **方位マップ画像 `scripts/sns-map.js`**: 出発地から見た今月の最大吉方を日本地図上に塗り、方位にある旅先を番号で示す Instagram 用画像(1080x1350)を、本命星ごとに自動生成します(表紙・お休みの星のまとめ付き)。例: `NODE_PATH=$(npm root -g) node scripts/sns-map.js 2026-10-15 tokyo out/` 背景は既定で「生成りの和紙」(方位盤・星・霞雲・青海波をごく薄く配置、`scripts/washi-bg.js`)。どの星・月でも同じ背景になり、末尾に `plain` を付けると無地になります。
9. **リール動画 `scripts/sns-reel.js`**: 「自分の星で止めてね」形式の縦長動画(1080x1920・約24秒・MP4)を生成します。フック → 9つの本命星を2秒ずつ(最大吉方を方位盤で表示) → 無料診断への誘導、の構成です。動画のエンコードには optionalDependencies の `ffmpeg-static` を使います(サーバーのデプロイでダウンロードに失敗しても止まらないよう optional にしています)。例: `NODE_PATH=$(npm root -g) node scripts/sns-reel.js 2026-10-15 tokyo out/`(第4引数は背景: washi(既定・カルーセルと共通の和紙) / plain / sunrise / sky / wave)
10. **星別ショートリール `scripts/star-reel.js`**: 1つの本命星だけを取り上げる約20秒の縦長リールです(画面8枚前後をクロスフェードでつなぐ)。フック → 星の特徴 → 方位盤 → 旅先を1か所ずつ(距離・マイルの目安・見どころ)→ 旅のポイント → 保存と無料診断への誘導、の構成で、吉方位がない月は「お休みの月」の過ごし方と次の最大吉方を表示します。5・6番目の引数にイラストを渡すと、最初と最後の画面に入ります。例: `NODE_PATH=$(npm root -g) node scripts/star-reel.js 2026-10-15 5 tokyo out/`
11. **漫画リール `scripts/manga-reel.js`**: ChatGPT などで作った4コマの絵(吹き出し・文字なし)に、セリフの吹き出しとテロップを重ねて、和紙背景の縦長リール(1080x1920・MP4)にします。セリフは1つずつ表示し、秒数は文字数から自動で決めます。シナリオ JSON の形式はファイル先頭のコメント参照。例: `NODE_PATH=$(npm root -g) node scripts/manga-reel.js scenario.json out/`
12. **リールの表紙 `scripts/reel-cover.js`**: リールのカバー画像(1080x1920)を和紙背景で作ります。プロフィールの一覧で切り取られる縦3:4の範囲に文字と絵を収めます。例: `NODE_PATH=$(npm root -g) node scripts/reel-cover.js out/cover.jpg "2026年10月の吉方位" "**七赤金星**さん\n10月は\n北西へ🧭"`
13. **12か月の吉方位カレンダー `scripts/star-calendar.js`**: 公式LINEの登録特典用に、本命星ごとの12か月分の最大吉方を一覧にした画像(1080x1350)を9枚作ります。例: `NODE_PATH=$(npm root -g) node scripts/star-calendar.js 2026-10-15 out/`
14. **文字スライド画像 `scripts/sns-images.js`**: マイル術などの文字中心の投稿用に、スライド定義(JSON)から同じデザインの 1080x1350 の JPEG を生成します。Playwright は依存に含めていないため、インストール済みの環境で `NODE_PATH=$(npm root -g) node scripts/sns-images.js slides.json out/` のように実行します。

```bash
npm install

```

`http://localhost:3000` にアクセスすると診断フォームが表示されます。

### Stripe決済について

`STRIPE_SECRET_KEY` を設定しない場合、有料コンテンツの販売は**停止**し、結果ページには「近日スタート予定」と表示されます(公開サイトで誰でも無料で有料機能を開けてしまわないため)。
開発時は `.env` で `MOCK_PAYMENTS=true` にすると、「月額会員になる」「買い切りで見る」ボタンで即座に購入済み扱いになります(`.env.example` は true になっています)。

本番で実際に課金する場合は以下を設定してください。

```
STRIPE_SECRET_KEY=sk_live_xxx (またはテスト用 sk_test_xxx)
STRIPE_WEBHOOK_SECRET=whsec_xxx
BASE_URL=https://your-domain.example.com
```

Stripeダッシュボードで Webhook エンドポイント `POST /webhook/stripe` を登録し、
`checkout.session.completed`・`customer.subscription.updated`・`customer.subscription.deleted` イベントを購読してください
(後ろ2つは月額会員の更新・解約の反映に使います)。

## 計算ロジックについて

- **本命星**: 立春(2/4)を年の区切りとし、生まれ年の西暦を1桁になるまで足した値から `11 - n` で算出する一般的な方法です。
- **年盤・月盤**: 年盤の中宮星は本命星と同じ計算で求めます。月盤は、寅月(2月)の中宮星を年の十二支で決め(子卯午酉年→八白、丑辰未戌年→五黄、寅巳申亥年→二黒)、そこから1ヶ月ごとに1つずつ戻します。月の区切りは節入り日(概算の固定日)です。
- **最大吉方**: 年盤・月盤の両方で、五黄殺・暗剣殺・本命殺・本命的殺・歳破(年盤)/月破(月盤)にあたらず、本命星と相生・比和の星が回座している方位です。本命星が中宮に入る盤は「八方塞がり」として吉方位なしとします。月命星による月命殺・月命的殺は考慮していません。
- **方位の基準地点**: 住所は国土地理院の住所検索API(`/api/geocode` がサーバー側で中継)で座標に変換します。番地・丁目は落とした地名と、小数第2位(約1km)に丸めた座標だけを保存します。ブラウザの現在地、または21都市からの選択にも対応しています。
- **方位の区分**: 東西南北を各30度、四隅を各60度とし、真北基準・大圏コースの出発方位(正距方位図法)で判定します。

2026年9月〜11月の年盤・月盤と、本命星ごとの最大吉方は、九星気学の実務者が目視で確認済みです(2026-09-25)。
吉方位の取り方は流派によって異なります。独自のやり方に合わせたい場合は `src/lib/houi.js` の判定条件を変更してください。
旅先の追加・紹介文の変更・必要マイル目安の更新は `src/data/places.js` を編集してください。

## 法的な注意事項

`public/index.html` 等に「娯楽目的である」旨の免責表記を入れています。
`public/tokushoho.html`(特定商取引法に基づく表記)・`public/terms.html`(利用規約)・`public/privacy.html`(プライバシーポリシー)の
テンプレートを用意していますが、`[事業者名を記入してください]` 等のプレースホルダー箇所は
実際の事業者情報に置き換えてから公開してください。プレースホルダーのまま公開すると法令違反になります。

## デプロイ

### 無料で最短公開する(カード登録不要・初めての方向け)

決済(Stripe)の設定をしなくても、無料診断部分は今すぐ公開できます。以下の手順で進めてください。

1. [Render.com](https://render.com) にアクセスし、GitHubアカウントで無料サインアップ(クレジットカード登録は不要です)。
2. ダッシュボードで「New +」→「Blueprint」を選び、`yuppi314/my-tool` リポジトリを選択します。
3. リポジトリ内の `render.yaml` を自動で読み込み、無料プランのWeb Serviceが作成されます。
4. `BASE_URL` の入力を求められたら、Renderが発行するURL(例: `https://kippou-mile-travel.onrender.com`)を入力します(一度作成してURLが確定してから設定し直しても構いません)。
5. `ADMIN_TOKEN` は好きな文字列(他人に推測されにくいもの)を入力してください。
6. 数分待つとURLが発行され、誰でもアクセスして無料診断が使えるようになります。

> 注意: 無料プランは永続ディスクが使えないため、Renderが再起動(15分アクセスがないと休止→次のアクセスで再起動)するとリード・診断データはリセットされます。
> 診断結果のURLには本命星と丸めた地点が含まれるため、データが消えても無料の結果ページは表示し続けられます。
> 「ユーザーが増えてきたので有料プランにしたい」というタイミングで、`runtime: docker` + 永続ディスク構成に切り替えてください(下記「本格運用する場合」参照)。

決済(カレンダーの買い切り・月額会員)は `STRIPE_SECRET_KEY` を設定するまで販売停止(近日公開表示)なので、
このステップでは何も設定しなくて大丈夫です。準備ができたら教えてください、Stripe連携を一緒に進めます。

### 本格運用する場合(Docker + 永続ディスク)

ユーザー数が増え、リードや購入データを失いたくない段階になったら、Docker + 永続ディスクの構成に切り替えます。

`Dockerfile` を用意しているため、Docker対応のホスティング(Render / Railway / Fly.io など)にそのままデプロイできます。
SQLiteでデータを永続化するため、コンテナの `/app/data` に永続ディスク(ボリューム)をマウントしてください。

Renderの場合は `render.yaml` の `runtime` を `docker` に、`plan` を `starter` 以上に変更し、
`disk` セクション(`mountPath: /app/data`)を追加してください。`STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` も
このタイミングで環境変数に設定します。

手動でDockerを動かす場合:

```bash
docker build -t kippou-mile-travel .
docker run -p 3000:3000 -v $(pwd)/data:/app/data --env-file .env kippou-mile-travel
```

## 家事の引き継ぎ表(LINE 連携)

大人になった子どもに家事を「お手伝い」ではなく「担当」として引き継ぐための、LINE 公式アカウントと Web ページのツールです。
吉方位ツールと同じサーバーで動き、データは同じ SQLite に `kaji_` で始まるテーブルとして保存されます。

- **LINE でできること**: 「家族を作る」「参加 家族コード」「親で参加 家族コード」「ごちそうさま」「片付けた」「おねがい 〜」「ページ」「ランキング」「名前 〜」「コード」
- **食後タイマー**: 誰かが「ごちそうさま」と送ると、子どもに「片付けた」ボタン付きの LINE が届きます。30分以内に片付けが記録されないと、**親に LINE で知らせます**(1回だけ)。間に合えば経験値2倍。
- **今日のおねがい**: 親が「おねがい 19時までにお米をといでおいて」と送ると子どもに届き、「引き受けた」「できた」で親に知らせます。子どもからのおねがいは親に届きます。
- **Web ページ `/kaji/?t=本人専用トークン`**: LINE で「ページ」と送ると届くリンクから開きます。家事ごとの完了チェックリスト、経験値・レベル・連続記録、今週のランキング、ごほうび設定、ありがとうボタン、引き継ぎの4段階、家事の追加(親のみ)。
- **家族ごとに分かれる**: 家族コード単位でデータが分かれるので、友達の家族も同じ LINE アカウントで使えます。Claude のアカウントは不要です。

### LINE の設定

1. [LINE Official Account Manager](https://manager.line.biz/) で公式アカウントを作る(吉方位ツールとは別に「家事」用を作るのがおすすめ)。
2. 設定 → Messaging API を有効にし、[LINE Developers](https://developers.line.biz/console/) でそのチャネルを開く。
3. 「チャネル基本設定」の **チャネルシークレット** を `LINE_CHANNEL_SECRET` に、「Messaging API設定」で発行した **チャネルアクセストークン(長期)** を `LINE_CHANNEL_ACCESS_TOKEN` に、Render の環境変数として入れる。
4. 「Messaging API設定」の Webhook URL に `https://(RenderのURL)/webhook/line` を入れ、「Webhookの利用」をオンにして「検証」を押す。
5. LINE Official Account Manager の 応答設定 で「応答メッセージ」をオフにする(自動返信と bot の返事が重なるため)。
6. (任意)リッチメニューに「ごちそうさま」「片付けた」「ページ」「ランキング」をテキスト送信のボタンとして置くと、文字を打たずに使えます。

`LINE_CHANNEL_ACCESS_TOKEN` が未設定のときは LINE に送らず、送る予定のメッセージをサーバーのログに出します。

### 運用上の注意

- **Render の無料プランでは使えない部分があります。** 無料プランは15分アクセスがないと休止するため、「30分後に親に知らせる」タイマーが動きません。また再起動・再デプロイのたびに家族や記録が消えます。家族で使い始める前に、上の「本格運用する場合」の構成(starter プラン + `/app/data` の永続ディスク)にしてください。
- **LINE の送信数**: 無料プランは月の送信数に上限があります。返信(reply)は数えられず、bot からの push だけが数えられます。食事1回あたり「子どもの人数」通、期限切れのときは「親の人数」通です。`KAJI_NOTIFY_DONE=true` にすると、片付けたときも親に知らせます(その分通数が増えます)。
- 本人専用リンクを知っている人は、その人として記録できます。リンクは家族以外に教えないでください。
